Technical summary

Strong teaching systems, uneven scientific assurance

The portfolio is generally reproducible and candid about educational scope, but polished dashboards sometimes outrun the evidence beneath them.

Decision: keep the portfolio as teaching material, but do not treat its headline model metrics as deployment evidence. Prioritize best-checkpoint selection in Project 02, independent validation for Projects 01/03/04/10, and uncertainty reporting across all modeled projects.

Scope, definitions, and method

Static evidence, bounded runtime checks, no source modification

Scope

All completed Part 2 projects, 00–10. Project 05’s vendored skills were treated as third-party reference material; its integration and generated evidence were audited. Part 1 was excluded.

Rubric

Methodology, reproducibility, leakage control, evaluation, and implementation each contribute 20%. A “high” issue can coexist with a good score when compensating controls are strong.

Evidence limits

This is a repository snapshot audit, not a production security review, dataset-license opinion, clinical validation, or independent rerun of every expensive training job. Existing artifacts were checked against code paths.

Claim taxonomy

Descriptive results are separated from predictive evidence. Association, clustering, anomaly ranking, and observational cuts are not treated as causal. Synthetic evaluation is labeled as such.

Control roadmap

  1. Stop invalid checkpoint/model selection: retain the best validation checkpoint in Project 02 and reserve a final test set in Project 10.
  2. Add independent robustness: temporal/spatial splits for taxi and groceries; held-out stability for clustering.
  3. Quantify uncertainty: bootstrap or repeated-split intervals for headline metrics and subgroup performance.
  4. Turn manual demos into executable claims: add numerical and accessibility tests to Projects 00 and 08.
